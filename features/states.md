# Features · 通用页面状态

> 所有页面都必须处理的通用状态。主题可以自定义**视觉**，但**语义不能丢**。

---

## 状态清单

| 状态 | 触发 | 必备呈现 | 禁止 |
|---|---|---|---|
| **loading** | 首次加载 | 骨架屏 / 加载指示 | 空白页无反馈 |
| **empty** | 数据为空 | 空状态文案 + 引导动作 | 假装有数据 |
| **error** | 请求失败 | 错误提示 + 重试 | 白屏 |
| **partial** | 后台刷新中（有旧数据） | 保留旧数据 + 轻提示 | 清空重加载 |
| **outdated** | 刷新失败（有旧数据） | 展示旧数据 + 明确「可能过期」警示 | 静默显示旧数据当新数据 |
| **forbidden** | 403 | 403 页面（无权限说明） | 跳首页无解释 |
| **unauthenticated** | 401 | 跳登录（带 `next`） | 卡死 |
| **not_found** | 404 | 空状态（资源不存在） | 当错误页 |
| **not_implemented** | 501 | 「该功能尚未开放」 | 假装成功 |
| **maintenance** | 503 | 维护提示 | — |

---

## 关键原则（主仓硬约束）

1. **绝不假成功**：后端未实现（501）或端口未装配（5xx）时，前端必须显式提示，
   不得渲染空列表/零值冒充真实数据。
2. **不丢旧数据**：后台刷新失败时保留上次成功数据（`outdated` / `partial`），
   而非清空（避免闪烁与数据丢失）。
3. **错误文案**：统一走 `shared/errors` 的 `getErrorMessage`（已处理脱敏）。
4. **超时/重试**：依赖类错误（`dependency_*`）提示稍后重试。

---

## 设置页示例（已有实现参考）

`apps/host/src/pages/settings/components` 的 `resolveSettingsQueryState` +
`SettingsFeedbackGate` 实现了上述 `partial` / `outdated` 状态——主题应复用同类语义。
